1. Contexte et Objectifs du Projet

1.1 Contexte médiatique

Le paysage médiatique marocain est riche et fragmenté : des dizaines de sites d'information publient chaque jour des centaines d'articles en arabe, français et anglais. À côté de ces sources locales, les grandes chaînes internationales (Al Jazeera, BBC, CNN, Reuters) couvrent les mêmes événements avec un regard extérieur.

Il n'existait pas jusqu'ici d'outil unifié permettant de collecter, normaliser, comparer et visualiser cette information de manière automatisée et temps-réel.

Problème résolu : un analyste qui veut savoir « quels sujets dominent l'actualité marocaine cette semaine ? » devait visiter manuellement 8 sites, lire des articles en 3 langues et consolider ses notes dans Excel. MediaPulse automatise tout ce processus en quelques minutes.

2.2 Architecture Medallion — Trois couches de données

CoucheChemin MinIOFormatRôle
🥉 Bronze bronze/source=X/date=YYYY-MM-DD/<hash>.json JSON brut Donnée telle que scrapée, immuable. Source de vérité.
🥈 Silver silver/source=X/date=YYYY-MM-DD/<hash>.json JSON nettoyé HTML strippé, encodage normalisé, langue détectée, dédupliqué.
🥇 Gold gold/table=X/run_date=YYYY-MM-DD/data.json JSON agrégé Top keywords (TF-IDF), tendances, comptages journaliers par source.

2.3 Flux de données de bout en bout

1

Scraping (batch ou streaming)

Le GenericArticleScraper crawle les pages d'index de chaque source, identifie les URLs d'articles via regex, télécharge et parse le HTML avec BeautifulSoup. Chaque article est validé par le modèle Pydantic Article (titre, contenu, URL, langue, pays, timestamps).

2

Publication Kafka

Le KafkaProducer sérialise l'article en JSON et le publie sur le topic raw-articles. En mode batch direct, le BronzeWriter écrit directement dans MinIO sans passer par Kafka.

3

Consommation et stockage Bronze

Le KafkaConsumer lit les messages par micro-lots de 50, les persiste sous bronze/source=X/date=D/<url_hash>.json dans MinIO. Le chemin est partitionné par source et par date de publication.

4

Transformation Bronze → Silver

Le pipeline nettoie les champs (strip HTML, NFKC Unicode, entités HTML), détecte la langue via langdetect, calcule un hash SHA-256 de l'URL pour la déduplication. Les records qui échouent à au moins une des 6 règles de validation sont rejetés vers silver/_rejected/ avec la raison de rejet.

5

Agrégation Silver → Gold

Lecture des fichiers Silver, tokenisation multi-langue (arabe + latin), calcul TF-IDF pour les top-50 keywords, agrégation des tendances quotidiennes par sujet, comptages par source et par pays. Résultats écrits en Gold partitionné par run_date.

6

Chargement Warehouse

Le WarehouseLoader lit les fichiers Gold, résout les clés de dimension (upsert dans dim_source, dim_date, dim_category) puis insère les faits dans fact_articles, fact_keyword_frequency, fact_daily_trends.

7

Visualisation

Grafana se connecte au warehouse PostgreSQL via le datasource provisionné automatiquement. Le dashboard MediaPulse News Intelligence affiche les comptes journaliers, la répartition linguistique, les top-keywords et le score de qualité en temps réel.

3. Choix Technologiques et Justifications

3.1 Ingestion et Streaming

Python 3.11
Langage principal

Riche écosystème web scraping (requests, BeautifulSoup, lxml), NLP (spaCy, langdetect), data (pandas). Typage strict avec Pydantic.

Apache Kafka (Confluent 7.6)
Bus de messages

Découplage producteur/consommateur, durabilité des messages, possibilité de replay. Indispensable pour un pipeline de scraping à haute fréquence. Topic raw-articles avec réplication factor 1 (dev).

Pydantic v2
Validation des données

Modèle Article avec validation stricte (URL, langues ISO 639-1, timestamps UTC). Rejet immédiat des données malformées dès l'ingestion.

BeautifulSoup4 + lxml
Parsing HTML

Parsing robuste des pages d'actualité. Sélection d'articles par patterns regex d'URL. Tolérant aux HTML malformés courants sur les sites d'information.

3.2 Stockage des Données

MinIO
Data Lake (Bronze/Silver/Gold)

Compatible API S3, déployable on-premise. Stockage objet partitionné par source et date — permet un scan sélectif sans lire l'intégralité du lac. Remplace S3 AWS dans un contexte académique.

PostgreSQL 16
Entrepôt analytique

Schéma en étoile sous le namespace warehouse. Extensions pgcrypto pour les UUIDs. Vues SQL pré-calculées pour les dashboards (daily_article_counts, language_distribution, data_quality_score).

Redis
Broker Celery (Airflow)

Broker léger pour les tasks Airflow CeleryExecutor. Faible latence, simple à opérer en développement.

Architecture Medallion
Design pattern

Bronze (raw), Silver (curé), Gold (agrégé) — chaque couche est immuable et rejouable. Permet un debugging progressif et une traçabilité complète de la data lineage.

3.3 Pipeline de Transformation

langdetect
Détection de langue

Détection automatique de l'arabe, anglais, français. Seed fixe (=0) pour la reproductibilité. Fallback sur le language_hint de la source en cas d'échec.

spaCy
NLP / tokenisation

Tokenisation multilingue pour l'extraction de keywords. Support du bloc Unicode arabe (U+0600-U+06FF). Calcul TF-IDF fait maison sur base de la fréquence brute.

pandas
Agrégation Gold

Lecture et agrégation des fichiers Silver JSON en DataFrames. Calcul des comptages journaliers, top-keywords, tendances par source.

python-dateutil
Normalisation temporelle

Parsing de dates dans tous formats (ISO, RFC, timestamps journaux). Conversion systématique en UTC pour la cohérence dans le warehouse.

3.4 Orchestration, Visualisation et Monitoring

Apache Airflow 2.9.3
Orchestration

5 DAGs : scrape batch, Bronze→Silver, Silver→Gold, chargement warehouse, contrôle qualité. CeleryExecutor pour la scalabilité horizontale. DAGs versionnés avec le code source.

Grafana 11.1
Dashboards

Provisionnement automatique (datasource PostgreSQL + Prometheus). Dashboard MediaPulse News Intelligence défini en JSON, versionnée dans le repo.

Prometheus
Métriques système

Scrape le postgres-exporter (port 9187) et le kafka-exporter (port 9308). Règles d'alerte pour données périmées et chutes du score de qualité.

Metabase
Analytics self-service

Interface no-code pour explorer le warehouse PostgreSQL. Idéal pour les équipes métier non-techniques. Connecté à la même base que Grafana.

4. Déploiement

4.1 Docker Compose

L'intégralité du stack est containerisé. Le fichier mediapulse/docker-compose.yml définit tous les services, réseaux et volumes. Les images applicatives (scraper, Airflow) sont construites localement à partir de Dockerfile (Python 3.11-slim) et Dockerfile.airflow. 

# Démarrage complet du stack
Copy-Item mediapulse\.env.example mediapulse\.env   # configurer les secrets
cd mediapulse
docker compose up --build

# Mode demo (seed warehouse + Grafana prêt)
docker compose --profile demo up --build demo-seed

5.3 CLI Opérateur

Depuis le répertoire parent architecture-project/, le CLI python -m mediapulse offre toutes les commandes du pipeline :

# Diagnostic de connectivité (MinIO, Kafka, PostgreSQL)
python -m mediapulse doctor

# Appliquer le schéma warehouse (DDL)
python -m mediapulse apply-schema

# Scraper toutes les sources (batch)
python -m mediapulse scrape

# Scraper une source spécifique
python -m mediapulse scrape --source hespress

# Pipeline Bronze → Silver (toutes sources)
python -m mediapulse bronze-to-silver

# Pipeline Silver → Gold
python -m mediapulse silver-to-gold

# Charger le warehouse depuis Gold
python -m mediapulse load-warehouse

# Rapport de qualité
python -m mediapulse quality --layer silver
python -m mediapulse quality --layer gold

# Seed de données de démonstration (14 jours)
python -m mediapulse seed-demo --days 14 --articles-per-day 16

Exécution des tests

cd architecture-project
python -m pytest mediapulse/tests/ -v

6.2 Alertes Prometheus

Les règles d'alerte définies dans dashboard/prometheus-alerts.yml couvrent :

  • Données périmées : aucun nouvel article depuis > 6 heures → alerte StaleData
  • Score qualité bas : taux de rejet Silver > 20% → alerte HighRejectionRate
  • Consumer lag Kafka : lag > 1000 messages → alerte KafkaConsumerLag
  • PostgreSQL indisponible : scrape echoue → alerte PostgresDown

6.3 Metabase — Exploration self-service

Metabase (port 3000) se connecte à la même base PostgreSQL. Les équipes non-techniques peuvent créer leurs propres questions et tableaux de bord sans écrire de SQL, en pointant directement sur les tables du schéma warehouse.

Accès rapide aux dashboards : après docker compose up, ouvrir Grafana sur http://localhost:3001 → dossier MediaPulse → MediaPulse News Intelligence. Les données de démonstration sont disponibles via docker compose --profile demo up demo-seed.

7. Démonstration Fonctionnelle du Pipeline de Bout en Bout

7.1 Scénario de démonstration

La démonstration ci-dessous montre le pipeline complet depuis le scraping jusqu'à la visualisation, en environ 15 minutes avec les données de démonstration pré-générées.

A

Démarrer le stack avec données de démonstration

docker compose --profile demo up --build demo-seed
Démarre tous les services et génère 14 jours × 16 articles par source dans le warehouse PostgreSQL.

B

Observer le scraping en temps réel

Ouvrir Airflow sur http://localhost:8080 → activer le DAG mediapulse_batch_scrape → déclencher manuellement. Suivre les logs en temps réel : scraping Hespress, Akhbarona, BBC, etc.

C

Vérifier le Bronze dans MinIO

Ouvrir http://localhost:9001 → bucket mediapulse → naviguer dans bronze/ pour voir les articles JSON partitionnés par source=X/date=YYYY-MM-DD/.

D

Déclencher le pipeline Bronze → Silver → Gold

Dans Airflow, déclencher successivement mediapulse_bronze_to_silver puis mediapulse_silver_to_gold. Observer le décompte d'articles acceptés vs rejetés dans les logs.

E

Charger le warehouse et voir les dashboards

Déclencher mediapulse_load_warehouse. Puis ouvrir Grafana (http://localhost:3001) → dashboard MediaPulse News Intelligence : les graphiques se peuplent avec les données réelles scrapées.
